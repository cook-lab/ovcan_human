# Independent audit of recovered WES provenance

The recovered records substantiate the successful Sarek run, connect all 23 annotated VCFs to its VEP tasks, and reproduce the archived CNV file identities. They also expose several presentation errors in the cluster handoff. The cohort and variant/CNV calls are unchanged. The principal new analytical limitation is that CNV support is almost entirely on-target and further restricted by pooled-reference bin filtering.

This audit reads the returned records and the original workstation inputs; it does not execute recovered scripts, rerun callers or inspect cluster alignments that were not returned. The handoff report is treated as a set of claims to verify. Here `B` denotes `data/cluster_wes_retrieval/2026-09-05/ovcan_human_wes_handoff_2026-09-05/`. Files under that ignored directory are identified by path and SHA-256 in the evidence table.

## Read transformations, reference and annotation

The samplesheet lists provider BAM inputs. The successful trace includes separate mapped/unmapped SAMtools extraction, collate/FASTQ, concatenation and fastp steps. The exact low-level extraction flags are not among the selected executed commands, so they should not be invented from a workflow default. The fastp task command is explicit: paired inputs/outputs, adapter trimming disabled, adapter detection requested, 15-bp length requirement, and `--split_by_lines 200000000` (50 million four-line FASTQ records per output file target). No quality- or length-filter-disable option is present. Fastp 0.23.4 retains quality/N-base filtering by default; the embedded per-model filtering results document discarded reads. Nominal sequencing is 100+100 cycles. Twenty-two samples have mean read length exactly 100 before/after filtering; TOV81D has shorter means (~99.33/~99.38 bp), so nominal read configuration is not an assertion that every input read was 100 bp. [Exact fastp 0.23.4 option definitions](https://raw.githubusercontent.com/OpenGene/fastp/v0.23.4/src/main.cpp).

Selected successful commands and version files support BWA `0.7.18-r1243-dirty` with `-K 100000000 -Y -B 3`, GATK 4.5.0.0 duplicate marking with removal disabled, and interval-sharded BaseRecalibrator/ApplyBQSR using dbSNP 146, Mills/1000G gold-standard indels and the assembly38 known-indels resource. SAMtools versions vary by task (1.20 alignment sorting, 1.19.2 duplicate-stage conversion, 1.21 other conversion/merge tasks); a single blanket version would lose this detail. The recorded `dirty` suffix does not identify which build changes, if any, were present.

The returned assembly38 FASTA index and sequence dictionary agree with every local VCF contig length. They are useful reference identity evidence, including per-contig sequence MD5 identifiers in the dictionary, but do not substitute for a checksum of the full FASTA file. The sidecar SHA-256 values are:

- Dictionary: `07523b4a0afd1127ae909f92f8b3911aff096461aed7eff3f1acf5bdfc1dc103`.
- FASTA index: `edefd93c489dc1baefad312f40388089f8db5cf6dcc3ba0955669ead274e8b6b`.

The executed Mutect2 task uses only the tumour alignment, `1000g_pon.hg38.vcf.gz`, `af-only-gnomad.hg38.vcf.gz`, and F1R2 collection. FilterMutectCalls uses orientation priors, a contamination table and a tumour-segmentation table. These resources reduce artifacts and support filtering; they do not establish somatic origin or allele-specific copy number. The variant PoN is separate from the five CNV reference exomes.

VEP 113.0 uses cache 113/GRCh38 and the recorded `--everything --filter_common --per_gene --total_length --offline --format vcf` options. The [release-113 configuration](https://raw.githubusercontent.com/Ensembl/ensembl-vep/release/113/modules/Bio/EnsEMBL/VEP/Config.pm) defines `filter_common` as 1000 Genomes global frequency >0.01 exclusion. Report configuration and observed counts separately: all 23 pre-annotation record counts are preserved. The MAF converter then adds `common_variant` when any supplied gnomADe AFR/AMR/ASJ/EAS/FIN/NFE/SAS AF exceeds 0.0004. Every flag across 582,474 rows agrees with that rule. The vendored converter's default and tagging code are at `scripts/vendor/vcf2maf-1.6.22.pl`, lines 19 and 890–903. TOV3121D's conversion version/options are known; the original other-22 conversion command/version remain undocumented.

The complete observed downstream cascade is 582,474 annotated records → 19,816 VCF PASS → 16,081 MAF PASS → 15,995 after the additional aggregate-frequency cutoff → 6,194 coding/splice candidates. The aggregate fields are `gnomADe_AF`, `AF`, `AA_AF` and `EA_AF` (gnomAD exome, 1000 Genomes and ESP annotations), using a maximum of 0.001. Missing annotation is not proof of population absence.

The provider SeqCap EZ Exome v3 target file has 242,232 intervals, 63,564,965 bp, and bare chromosome names. The scratch copy is an ordered coordinate-identical file after adding `chr` prefixes; it has a different byte hash. The lifted output's interval names map to exactly 242,215 original intervals. The 17 missing originals exactly match the ignored list, and split mappings produce 242,421 output rows. Sorted variants preserve the coordinate multiset. This substantiates the transformation lineage without inventing the unavailable liftOver executable version, chain bytes or invocation.

The hg38 calling BED has 63,709,951 bp summed interval length but 63,514,049 distinct bases; overlaps account for the difference. The executed scatter command partitions rows without adding padding. The 290,475 CNV target bins have the same 63,514,049-bp union and are byte-identical to `output/wes_cnvkit_target_intervals.bed`. Their standard-chromosome subset used elsewhere is 63,465,385 bp. These are distinct denominators and must not be conflated. ## CNV provenance and actual measurement support

All 69 returned manual outputs (23 each of `.cns`, `.call.cns`, `.bintest.cns`) match every same-named archived copy. The current analysis uses `.cns` relative segments. The empirical pooled `reference.cnn` is already present in **35 byte-identical archived copies**, 26,875,054 bytes, SHA-256 `848c052274264ac544897977648860455ac742d89bc1de5edc7ece1ca185eeda`. It need not be requested again as a missing file. It is not copied into the public repository by this audit.

The normal-accession membership, reference file and manual command files support the intended pooled-reference workflow. The recovered `commands1.txt` contains the six corrected BAM invocations whose earlier `commands.txt` lines included extraneous bare sample tokens. This resolves the command-text ambiguity, but the manual-run execution log remains absent. The normal `bwa-mem2.txt` is a multiline recipe and the current wrapper selects the index step; neither proves an exact successful bwa-mem2 invocation/version. Sort/index logs provide narrower execution evidence. Do not describe an absent normal-QC file as never produced.

For every model, the CNR coordinate set exactly equals the retained set reconstructed from the pooled reference using the union of `|log2| > 5`, `spread > 1`, zero depth, and GC outside 0.3–0.7. These rules overlap; individual counts must not be summed. The target exclusions comprise a union of 85,769 bins. Counts meeting individual criteria are 15,625, 39,975, 41,206 and 22,738, respectively. This leaves 204,706 target bins before model-specific zero-depth removal. The same logic removes 1,786 antitarget bins. The [CNVkit reference-mask implementation](https://cnvkit.readthedocs.io/en/stable/_modules/cnvlib/fix.html) documents these operations; its rendered source is version 0.9.8, so the exact match to archived coordinate sets, rather than an assumed installed default, is the decisive check here.

Every tumour's original antitarget coverage has 42,705 zero-depth bins and only four positive bins. Zero-depth bins remain visible in intermediate CNR files but are not counted in segment probe totals: the latter equal the CNR positive-depth count for every model. This agrees with the recorded `--drop-low-coverage` behavior; the [CNVkit implementation](https://cnvkit.readthedocs.io/en/stable/_modules/cnvlib/cnary.html) removes zero-depth bins even when their normalized log2 value is not extremely low. There is no evidence here that the zero antitargets were interpreted as biological deletions in the segment summaries.

This reconciles apparently high sequencing coverage with a smaller CNV measurement set. Mosdepth measures coverage across the supplied calling intervals; CNVkit additionally masks bins using the external pooled reference. The resulting CNV profiles have about 204,000 retained target measurements and essentially no off-target validation. Their segment spans and span-based FGA are descriptive estimates across gaps, not direct observations at every base. This limits claims of intergenic resolution, absolute ploidy and complete genome-wide sensitivity, without changing the existing segment calls or patient denominators.

## Remaining gaps and manuscript consequences

The recovered material closes the major workflow/version, model mapping, target-definition and model-QC provenance gaps. It supports the cautious v8 WES methods and new technical-validation panels, with MAF PASS and target-support wording corrected.

Before depositing alignment files, resolve which retained CRAM version will be deposited and preserve its generating run/header/reference. The current bundle demonstrates interval-sharded ApplyBQSR and later launches into the same output directory, but lacks the alignments and header records needed to independently verify the reported overwrite dates, quickcheck results or byte equivalence. Do not label re-executed CRAMs as the exact original variant-calling input. Availability of genome-wide duplicate-marked QC is independently demonstrated and should remain the basis for mapping/depth denominators.

Remaining provenance retrievals are the full alignment-reference checksum, exact workflow source archive/local modifications and container identities, liftOver command/chain, original other-22 MAF conversion invocation, manual CNV successful-execution log, and per-normal coverage/QC records. These are engineering/archive tasks rather than invitations to invent protocols or launch new analyses. Their absence should be disclosed where not recoverable. The author-only acquisition items (DNA extraction/library preparation and the TOV81D provider pool alias), stock authentication, ethics and deposition accessions remain separate. No new MSI, HRD or allele-specific CNV analysis is required to complete this provenance audit.
