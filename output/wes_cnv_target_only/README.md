# Target-only relative CNV segments

These 23 files replace the archived hybrid-bin segments for downstream analysis. They were generated by [script 29](../../scripts/29_wes_cnv_target_only.py) from the original, reference-normalized CNR files after retaining rows whose `gene` is not `Antitarget`. Target rows, including their ratios and weights, were retained without numerical transformation. The source reference mask was unchanged. Large intermediate CNR files and runtime logs remain in ignored `tmp/wes_cnv_target_only_2026-09-06/`.

## Why this correction was necessary

Every model had only four positive antitarget bins, all overlapping capture targets. Their extreme normalized ratios biased some archived segment means, including two chromosome 1 gains. See [the independent assessment](../../reports/wes_cnv_coverage_2026-09-06/provenance_assessment.md) and its contributing-bin diagnostics. Removing all antitarget rows and rerunning segmentation avoids selectively adjusting those two means while retaining potentially affected breakpoints.

## Execution and validation

- Native CNVkit **0.9.10**, R **4.5.2**, DNAcopy **1.82.0**; see [runtime.json](runtime.json) for package versions, source hashes and parameters.
- CBS alpha 0.0001, native arm partitioning, `skip_low=True`, outlier factor 10, minimum-weight filter 0, one native worker per model and no optional CBS smoothing. Two models were processed concurrently.
- Original OV2295 and TOV2835EP CNRs reproduced all **202 archived segment boundaries, probe counts and log2 means exactly** per model. An additional control for the centring-sensitive OV1369-R2 reproduced all **248 segments exactly**; script 29 now requires all three control replays. [Baseline replay evidence](baseline_replay.csv). This is not byte-identical replay: archived CNS includes unused bootstrap-CI columns, and a few transferred weight/depth values differ by at most 0.001/0.01, respectively. Re-reading rounded CNR input rather than the original in-memory array can explain such last-digit differences. The segmentation values used downstream are identical.
- Target-only outputs contain **6,073 segments across all retained contigs** and **4,692,292 contributing target bins**, 203,913–204,064 per model. Every positive-depth target bin contributes; native filtering caused no further target-bin losses. Downstream autosomal segment counts use a different chromosome scope.
- Every output file hash, segment count and probe total was independently rechecked against [manifest.csv](manifest.csv).

The former OV2295 chromosome 1 artifact is incorporated into a 587-probe segment, chr1:143401653–149090427, raw log2 −0.087328. The corresponding TOV2835EP region is incorporated into a 6,724-probe segment, chr1:143401653–205021997, raw log2 0.0616882. These are newly estimated boundaries and values, not the fixed-membership sensitivity values reported in the earlier diagnostic.

## Reproduction

Use an existing environment with CNVkit exactly 0.9.10 and an R installation containing DNAcopy; this script does not install packages. For example:

```sh
OVCAN_CNV_PYTHON=/path/to/cnvkit-environment/bin/python \
  python3 scripts/29_wes_cnv_target_only.py --rscript /path/to/Rscript --workers 2
```

Launching script 29 with that environment's Python also works without specifying `--python`. The optional `OVCAN_DATA` points to a restored archived data root containing `cnvkit wes - new/`; every selected original CNR and CNS is checked against the existing source manifest. `--baseline-only` runs the three validation cases without generating target-only segments.

The files contain relative target-supported ratios. They do not establish absolute copy number, ploidy, allele-specific loss or complete off-target/intergenic coverage. Script 29 performs no additional alignment, coverage calculation, reference fitting, centering or integer copy-number calling. Bootstrap confidence intervals are not regenerated because the downstream analysis uses the native segment ratios/probe counts; their absence is not a statement about uncertainty being zero.
